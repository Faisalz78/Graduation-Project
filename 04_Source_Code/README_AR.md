# دليل تنظيم الكود

هذا هو مكان الكود الوحيد للمشروع داخل مجلد سطح المكتب. تطبيق الويب وFastAPI وترحيلات PostgreSQL واختبارات دورة الفاتورة والاستخراج والتدقيق والميزانيات وإدارة المشاريع والمستخدمين جاهزة، وبدأ تطبيق Expo بتسليم للدخول والرفع والمتابعة ثم جُمّد مؤقتًا. ابدأ من [دليل التشغيل](../RUN_LOCAL_AR.md).

| المجلد | مسؤوليته |
|---|---|
| web | تطبيق Next.js وTypeScript: الشاشات والمكونات وعرض بيانات API. |
| backend | FastAPI: الهوية والصلاحيات وقواعد العمل والتعامل مع قاعدة البيانات والملفات. |
| database/migrations | إنشاء الجداول وحماية سجلات التدقيق وبيانات الفاتورة ودورة المراجعة والاستخراج والتدقيق وأوامر الشراء والاستلام والحوكمة والإدارة؛ عشرة ترحيلات مرتبطة بـbackend/alembic.ini. |
| ai/document_intelligence | القراءة والاستخراج وQR وXML وتحويلها إلى ناتج موحد. |
| ai/financial_intelligence | تجارب التقييم المستقبلية؛ قواعد السعر والتكرار التشغيلية موجودة في خدمة FastAPI. |
| mobile | تطبيق Expo وReact Native: دخول آمن وقائمة وتفاصيل ورفع ومتابعة، ويستخدم FastAPI نفسه. |

## قواعد التنفيذ

- الإنجليزية لأسماء الملفات والدوال والجداول، والعربية للشرح وتجربة الاستخدام الأساسية.
- وحدات الخادم تجمع سلوك المجال نفسه، مثل الهوية أو الفواتير؛ الملفات المشتركة تقتصر على الإعدادات والهوية والاتصال والخدمات المشتركة فعلًا.
- Next.js وExpo يعرضان البيانات ويتعاملان مع API. صلاحيات القرار والحسابات مصدرها FastAPI.
- كل قاعدة بيانات لها تعريف واحد وترحيلات موثقة. كل مكتبة تُضاف بسبب واضح وتثبت نسختها المتوافقة.
- اختبارات الخادم تبقى قريبة من الخادم واختبارات الويب قريبة من الويب؛ خطط التقييم والنتائج المجمعة في `06_Testing_Evaluation` على مستوى المشروع.
- البيانات والملفات المرفوعة والأسرار لا توضع داخل ملفات المصدر أو مجلد الويب العام. تجهز ملفات إعدادات نموذجية بقيم توضيحية خالية من الأسرار.
- التعليقات تشرح سبب القرار عند الحاجة، والدوال والملفات تركز على مسؤوليات واضحة.
- طريقة التشغيل والاختبارات تكتب عند إعداد التطبيقات وتُجرب فعليًا؛ لا تُعرض أوامر مفترضة على أنها مجربة.

## خريطة الملفات المنفذة

| المكان | محتواه |
|---|---|
| `backend/app/core` | الإعدادات والاتصال والهوية والجلسات وحماية الطلبات. |
| `backend/app/routes` | مسارات الدخول والمشاريع والفواتير والموردين والحساب وأوامر الشراء والاستلام والحوكمة والتحليلات وإدارة النظام. |
| `backend/app/services` | التحقق من المستندات والحفظ والنطاق والحسابات والتدقيق والتحليل والحوكمة والميزانيات وإدارة الحسابات والمشاريع. |
| `backend/app/schemas` | التحقق من مدخلات المورد والفاتورة والمشتريات والميزانيات والإدارة. |
| `backend/app/models.py` | تعريف الجداول الستة والعشرين. |
| `backend/app/extraction_worker.py` | معالجة طابور PostgreSQL واستدعاء عملية الاستخراج بمهلة، مع استعادة الطلبات بعد الانقطاع. |
| `ai/document_intelligence` | قارئ PDF وOCR وZATCA TLV QR وUBL XML ومحلل الاقتراحات ومولد القياس ورسام معاينة صفحات PDF؛ لا يكتب بيانات الفاتورة. |
| `backend/app/seed.py` | حسابات ومشاريع التجربة؛ يعاد تشغيله دون تكرارها. |
| `backend/tests` | 196 اختبارًا للحسابات والملفات والصلاحيات والتزامن ودورة المراجعة والتدقيق والشراء والحوكمة والميزانيات وإدارة النظام باستخدام PostgreSQL مخصص للاختبار. |
| `web/src/app` | الدخول والقائمة والرفع والتفاصيل وتعديل البيانات والمشاريع والموردون والمشتريات والحوكمة واللوحة والميزانيات وإدارة النظام. |
| `web/src/components` | مساحة العمل والجلسة وعناصر الواجهة المشتركة. |
| `web/src/lib` | استدعاءات API والأنواع وتنسيق العرض. |
| `web/tests` | 23 اختبار متصفح للرفع والبيانات والمراجعة والاستخراج والتدقيق والشراء والحوكمة واللوحة والميزانية وإدارة النظام والكمبيوتر والجوال. |
| `mobile/src` | عميل TypeScript عربي، وشاشات الدخول والقائمة والتفاصيل والرفع، واستدعاء Bearer API وتخزين الجلسة في SecureStore. |

إصدارات الاعتماديات مثبتة في `backend/requirements.lock.txt` و`web/package-lock.json`. استخدم Ruff لتنسيق Python وفحصه، وPrettier لتنسيق الويب، وTypeScript للتحقق من الأنواع. إعداد أدوات التشغيل يوجد في `10_Deployment/Scripts` في جذر المشروع.

قواعد الحالات في `backend/app/services/workflow.py`، ومدخلاتها في `schemas/workflow.py`، والاختبارات في `tests/test_workflow.py`. واجهة الإجراءات والشارات في `web/src/components/invoice-workflow.tsx`، وتجربة المسار في `web/tests/workflow.spec.ts`. تظل قرارات العمل في الخادم؛ الواجهة تعرض allowed_actions وتتعامل مع رفض الطلب القديم.
